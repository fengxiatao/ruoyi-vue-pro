电话销售订单与仓库协同处理设计方案
一、场景背景
在电话销售场景中，客服与客户的通话可能持续较长时间，客户下单过程中会不断调整订单内容，包括添加、修改、删除商品，甚至取消整个订单。同时仓库需要根据客服的提交动态拣货、分货、验货和打包，因此需要一个灵活、高性能、低出错率的订单处理系统。
二、核心需求
1. 订单可以多次提交，每次提交都是对当前订单的一次变更。
2. 每次提交需与上次提交做差异比对，生成拣货、退货等仓库任务。
3. 提交前应展示差异变更内容，客服需确认后提交。
4. 未打包前可取消任务或变更订单内容。
5. 系统需保留所有变更记录以供追溯。
三、系统设计
3.1 架构概览
订单系统包括订单草稿、提交批次、仓库任务池三部分。订单草稿保存在缓存中供客服编辑；每次提交会生成提交批次（包括差异信息），提交后进入仓库任务池执行。
3.2 数据结构
（1）订单提交批次表 order_submit_batch：记录每次提交的版本信息；
（2）提交批次明细表 order_submit_batch_items：记录每次提交的商品及数量；
（3）差异表 order_submit_diff：记录新旧版本之间的商品变更；
3.3 差异比对逻辑
每次提交需与上一次提交对比商品明细，生成新增、减少或变更记录，以便仓库明确拣货或退货的任务目标，避免重复拣货或误操作。
3.4 状态管理
订单主状态包括草稿、待确认、已确认、已打包、已发货等；每个提交批次独立管理状态，支持取消、重提。仓库任务基于提交批次而非订单整体生成。
四、前端体验建议
1. 每次提交前展示变更对比内容，明确增减情况；
2. 草稿自动保存，支持恢复上次编辑内容；
3. 提交历史记录支持查看并对比差异；
五、总结
采用批次提交 + 差异对比 + 多状态管理机制，可以最大化适应客服频繁变更订单的特点，同时保障仓库工作的高效和准确。该方案可扩展性强，适用于复杂商品处理场景。
